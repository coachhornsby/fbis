## Release decision

ci.yml is the canonical Pages authority. deploy-pages.yml retains its manual entrypoint but dispatches CI on main. PR CI remains TEST / BUILD. Every main push gets verification (no path exclusions). Main concurrency serializes active releases; GitHub may replace an older pending run with a newer equivalent main run. PR groups cannot cancel main. Production deploy lock never cancels an active deployment.

Validated SHA remains github.sha for checkout, build, upload and health comparison. The RELEASE RESULT job runs after validation/deployment even when either fails, publishes a JSON artifact and job summary, and fails closed unless validation, deployment, Cloudflare canonical SHA, live runtime SHA, all migration filenames, canonical tip registration, health, static UI and critical API checks pass. A main advancement is recorded separately; it never changes the intended SHA.

Machine-readable states: workflow pending/in_progress means EXPLICITLY_PENDING; failed verification produces BLOCKED with reasons; release-result.json VERIFIED_PRODUCTION identifies verified exact SHA. Earlier ancestors become SUPERSEDED only once a newer ancestor-descendant release is verified. Cancelled pending runs are not green CI.

Sport logic and research triggers are unchanged. No mass reruns, historical feature replay, or backfill replay is authorized by SHA lag alone.
